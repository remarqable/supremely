# Architecture

Supremely's detailed architecture is defined by the project's internal engineering blueprint.

This public document deliberately avoids duplicating or competing with that blueprint while the system is taking shape.

## Architectural intent

Supremely should remain:

- understandable;
- secure by design;
- easy to operate;
- easy to change;
- conservative about unnecessary dependencies;
- explicit about important boundaries and decisions.

## Source of truth

For implementation work, the project's blueprint and accepted Architecture Decision Records are authoritative.

As Supremely stabilizes, this document should evolve into a public map of the actual system: major components, boundaries, data flow, deployment model, and extension points.

It should describe what exists — not architecture we merely imagine building.

## Decisions

Material architectural decisions should be recorded in [`docs/adr/`](adr/).
